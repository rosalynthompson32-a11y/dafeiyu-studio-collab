# 常态工作流（五步流）

> 2026-10 现行版本 · 公开脱敏版
>
> 适用场景：一名人类验收官 + 若干模型席（主持／执行／审查／制作）的日常协作。
> **席位是槽位**：下文所列工具为参考实现，可等价替换成你自己的组合。
> 本文为我方内部规程的公开整理版，不含任何隐私与账号信息。

---

## 一、席别

| 席 | 定位 |
|---|---|
| **主持席**（Claude Code） | 总调度：议方案、按型派活、全程播报、转派改单、汇报结论 |
| **执行主力**（DSH / DeepSeek Harness） | 常规生产：文档／报告／简报／清单、呈现（网页·动画·图）、单文件小工具、数据整理、批量读写、**生成渲染类** |
| **审查席**（GPT，只读） | 方案复核、实跑终测与复测；不改文件 |
| **长图文席**（Qwen，执行岗） | 识图／看视频／长文本理解、PDF·PPT·Excel 制作、图文排版、多模态素材 |
| **代码设计席**（GLM，候补） | 系统／工具链／多文件工程、算法实现、协议与接口设计等精细化任务（默认仍归执行主力，按需分派） |

---

## 二、流程五步

1. **议方案** —— 主持＋审查席按需求先议（轻件一句话级；重件两分钟门禁）。
2. **派活** —— 主持按型定向，**随单附验收命令**；缺判据的派单由审查席当场退回（**生产方不得自带考卷**）。
3. **执行** —— 各席按型接活；全程向实时日志追加进度行。
4. **实跑终测** —— 审查席**只认实跑＋证据**；复测仍归审查席，范围写死：只测改动项；若改动触及已过项，则该方向全量重测。
5. **问题回环**（两层）——
   - **小瑕疵**（写法／格式／命名／次项缺漏）→ 审查席出改法清单 → 主持转**原生产者原会话**改 → 复测；**不上报人类**（防噪音）。
   - **实质问题**（方向错／崩坏／缺件／动了不该动的）→ 呈人类 → **人类与审查席议改** → 主持落单，返工归原会话。

## 三、类型定向

判据：**要不要做设计取舍？** 加之 **广度／深度** 取性。

| 类 | 归 | 典型／边缘例 |
|---|---|---|
| **常规** | 执行主力 | 文档／报告／呈现；单文件小工具；数据整理；批量读写、跨仓检索；偏广度的多功能件。单文件、一次跑通、无接口约定 → 常规 |
| **代码设计·精细化** | 代码设计席（默认主力） | 系统／工具链／多文件工程；算法实现；协议与接口设计；正确性敏感内核（仿真、解析器、调度器、读取器）。调 bug：要「定位＋设计修法」归代码设计席；只按现成改法执行归主力 |
| **长图文／物料** | 长图文席 | 识图／长文／PDF·PPT·Excel；跨域件按**最终产物**归类（产物是文档→长图文席；是代码→代码设计席） |
| **生成渲染**（图·视频） | 执行主力 | 生成类场景走程序化渲染等合法方式，判据随单；产出由主持终检（守生产与终检分离） |

**附则**：同技术两席皆能时（如 HTML／Canvas／SVG）——偏广度（多功能聚合）→主力；需深度发展（单向深挖、正确性密集）→代码设计席。模糊件由主持判；拿不准呈人类。

## 四、红线与闸门

**长图文席 · 红线三条**：
① 只在本职域内落地（长图文／物料），不接通用代码工程与系统类；
② 不改他人产物（改动归原生产者原会话）；
③ 动钱、动配置、不可逆 → 一律先报。

**终测闸门 · 两档**：
- 走审查终测：① 可执行产物要落地 ② 动钱／动配置／不可逆。其余轻装档日常件免测（防瓶颈）。
- 共享件例外：技能档／读取器／面板／启动链凡有改动，仍算任务、走终测。

**最小权限**：所有子进程调用按需授权；宁用受限工具组合，不用一键放行开关。

---

## 五、治理

- **双层治理**：治理索引（权威页指针）＋ 规程文件；同一事实禁止两处双写，互指不复制。
- **验收门操作实况**：裁判时长方差大 → 判死线 ≥ 15 分钟；空手卡易陷询证轮回 → **验收探针必须带真工件**。
- **登记册**：PENDING 登记（挂起／待办）随时可查。
- **收撤纪律**：旧章原文保留、文首加收口注指向现行页；废规要清（不留歧义）。
